# Развёртывание расписания через GitHub и Cloudflare

Инструкция для Windows 10. Она относится к проекту расписания в этой папке. Файл `password-vault/docs/DEPLOY.md`, который ты приложила, описывает другой проект — менеджер паролей; его команды и настройку Google Drive переносить сюда нельзя.

## Что потребуется

- Аккаунт [GitHub](https://github.com/) и приложение [GitHub Desktop](https://desktop.github.com/). GitHub Desktop поддерживает Windows 10 64-bit ([системные требования](https://docs.github.com/en/desktop/overview/supported-operating-systems-for-github-desktop)).
- Аккаунт [Cloudflare](https://dash.cloudflare.com/).
- Аккаунт Telegram и бот от [@BotFather](https://t.me/BotFather).
- Домен покупать не нужно: Cloudflare выдаёт HTTPS адрес `https://usm-life.<твой-поддомен>.workers.dev` ([как работают workers.dev адреса](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/)).

**Google OAuth не понадобится:** текущий проект не использует Google Drive или Google OAuth. Для интерактивной карты и планировщика маршрутов используются ключи Google Maps Platform (раздел 9), но авторизация пользователей через Google не требуется — всё работает внутри Telegram.

## 1. Создай бота и сохрани необходимые значения

В Telegram открой [@BotFather](https://t.me/BotFather), отправь `/newbot`, задай имя и username, сохрани токен `BOT_TOKEN` в менеджере паролей.
Никому не пересылай его.

Создай длинный webhook secret из латинских букв, цифр, `_` и `-` (от 32 символов). Он должен отличаться от bot token.

## 2. Создай приватный GitHub-репозиторий из проекта

1. Установи GitHub Desktop и войди в свой аккаунт.
2. Выбери **File → Add Local Repository…** и укажи папку проекта `C:\Users\mellory\Desktop\USM`.
3. Если GitHub Desktop сообщает, что репозиторий ещё не создан, выбери **create a repository**. Название, например, `usm-life`; выбери **Private**.
4. Убедись, что в списке изменений нет `.env`, `.env.local` или видео из `demovideo/`. Эти файлы исключены через `.gitignore`.
5. Нажми **Commit to main**, затем **Publish repository**. Проверь, что переключатель **Keep this code private** включён.

Не добавляй секреты в файлы проекта, описание коммита или сообщения GitHub.

## 3. Создай базу данных Cloudflare D1

В Cloudflare Dashboard открой **Workers & Pages → D1 SQL Database → Create database**. Назови базу `usm-life`.

Открой созданную базу → **Console**. Открой локальный файл `worker/migrations/0001_initial.sql`, скопируй всё содержимое в Console и нажми **Execute**. SQL создаёт личные настройки, занятия, ДЗ, отметки уведомлений и состояние транспорта. Cloudflare описывает запуск SQL через D1 Console в [руководстве D1](https://developers.cloudflare.com/d1/get-started/).

Скопируй `database_id` этой базы и открой `worker/wrangler.toml` в проекте. Замени `REPLACE_WITH_D1_DATABASE_ID` на скопированный ID, сохрани файл и отправь изменение в GitHub через GitHub Desktop (**Commit to main → Push origin**).

## 4. Подключи GitHub к Cloudflare Workers Builds

1. В Cloudflare открой **Workers & Pages → Create application → Get started → Import a repository**.
2. Разреши Cloudflare доступ только к приватному репозиторию `usm-life`, выбери его и ветку `main`.
3. Имя Worker задай точно `usm-life` — оно совпадает с `name` в `worker/wrangler.toml`.
4. Укажи корневую папку репозитория `/`.
5. Настрой сборку:

   - **Build command:** `npm run build`
   - **Deploy command:** `npm run deploy --workspace=@usm/worker`

Cloudflare сам устанавливает зависимости, выполняет `npm run build` (собирает только Mini App), затем запускает Wrangler из каталога Worker через npm workspace. Это важно: запуск Wrangler прямо из корня npm-workspace приводит к ошибке определения приложения. Подробнее — [Workers Builds для monorepo](https://developers.cloudflare.com/workers/ci-cd/builds/advanced-setups/). При первом подключении дай Cloudflare создать собственный токен сборки. Не вставляй личный API token в файлы GitHub.

## 5. Добавь переменные Worker в Cloudflare

В Cloudflare открой Worker `usm-life` → **Settings → Variables and Secrets**. Добавь runtime-переменные:

| Имя                       | Значение                                                                                 |
| ------------------------- | ---------------------------------------------------------------------------------------- |
| `BOT_TOKEN`               | токен из BotFather, тип Secret                                                           |
| `TELEGRAM_WEBHOOK_SECRET` | созданный webhook secret, тип Secret                                                     |
| `MINI_APP_URL`            | `https://usm-life.<твой-поддомен>.workers.dev`                                           |
| `GOOGLE_MAPS_SERVER_KEY`  | API-ключ Google Maps для Routes API (серверный), тип Secret                              |
| `GOOGLE_MAPS_BROWSER_KEY` | API-ключ Google Maps для Maps JS API (клиентский), тип Secret                            |
| `TRANZY_API_KEY`          | _(опционально)_ API-ключ Tranzy, тип Secret                                              |
| `TRANZY_VEHICLES_URL`     | `https://api.tranzy.ai/v1/opendata/vehicles` (уже задан в `wrangler.toml`)               |
| `TRANZY_REFRESH_MINUTES`  | `5` (период опроса транспорта в минутах, уже задан в `wrangler.toml`)                    |
| `TRANZY_AGENCY_ID`        | _(опционально)_ ID агентства, если требуется зафиксировать конкретного оператора вручную |

В разделе **Bindings** должен быть D1 binding `DB`, привязанный к базе `usm-life`. Он описан в `worker/wrangler.toml`; если Cloudflare предложит подтверждение binding, выбери именно созданную базу.

Узнать точный `<твой-поддомен>` можно на странице **Workers & Pages** в Cloudflare. Включи маршрут `workers.dev` для Worker. После добавления или изменения переменных нажми **Deploy** либо отправь новый commit, чтобы Cloudflare опубликовал актуальную версию.

## 6. Проверь публикацию

Открой `https://usm-life.<твой-поддомен>.workers.dev/health`. Должен появиться JSON с `"ok":true`. API, webhook и `/health` настроены на запуск Worker до SPA-резервного маршрута. Открой основной URL: Mini App должен показывать интерфейс, но API работает только в Telegram с валидным `initData`.

## 7. Подключи Telegram webhook

В корне проекта скопируй `.env.local.example` в `.env.local`, заполни `BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` и `WORKER_URL` (`https://usm-life.<твой-поддомен>.workers.dev`). Этот файл исключён из Git.

Установи Node.js 22.18+ с [официального сайта](https://nodejs.org/) и открой PowerShell в корне проекта. Выполни:

```powershell
node --env-file=.env.local scripts/set-webhook.mjs
```

Ожидаемый ответ — `Webhook подключён.` Скрипт отправляет токен и секрет непосредственно в запросе к Telegram Bot API и не печатает их в консоль.

## 8. Привяжи Mini App в BotFather

В [@BotFather](https://t.me/BotFather) открой `/mybots` → выбери бота → **Bot Settings → Menu Button → Configure menu button**. Укажи заголовок `Открыть расписание` и тот же HTTPS URL Worker. Если Telegram попросит домен — используй поддомен `workers.dev`, назначенный Cloudflare. Затем отправь боту `/start` и открой Mini App.

После проверки каждое изменение в `main` можно отправлять кнопкой **Push origin** в GitHub Desktop; Workers Builds автоматически пересоберёт и развернёт приложение.

## 9. Настройка Google Maps Platform (Интерактивная карта и маршруты)

Для работы интерактивной карты Кишинёва со слоем пробок и планировщика маршрутов A → B используются сервисы **Google Maps Platform**. В соответствии с правилами использования (Terms of Service) Google, результаты Google Routes API визуализируются строго на интерактивной подложке Google Maps.

В проекте используются два раздельных ключа API:

1. **`GOOGLE_MAPS_SERVER_KEY` (Серверный ключ)**
   - **Назначение:** Используется бэкендом Cloudflare Worker в эндпоинте `GET /api/trip/plan` для выполнения запросов к Google Routes API v2 (`TRANSIT` и `DRIVE` с включённым `TRAFFIC_AWARE`).
   - **Включение API:** В [Google Cloud Console](https://console.cloud.google.com/) включи **Routes API**.
   - **Ограничения ключа (API restrictions):** Выбери _Restrict key_ → разреши только **Routes API**.
   - **Ограничения приложений (Application restrictions):** Выбери _None_ (так как Cloudflare Workers выполняют запросы с динамических IP-адресов дата-центров Cloudflare).
   - **Установка в Worker:** Выполни в терминале:
     ```bash
     npx wrangler secret put GOOGLE_MAPS_SERVER_KEY
     ```
     и вставь ключ при запросе.

2. **`GOOGLE_MAPS_BROWSER_KEY` (Клиентский ключ)**
   - **Назначение:** Загружает Maps JavaScript API в Telegram Mini App для отображения интерактивной карты, маркеров троллейбусов Tranzy, слоя пробок TrafficLayer и полилиний маршрутов.
   - **Включение API:** В Google Cloud Console включи **Maps JavaScript API**.
   - **Ограничения ключа (API restrictions):** Выбери _Restrict key_ → разреши только **Maps JavaScript API**.
   - **Ограничения приложений (Website restrictions / HTTP referrers):** Выбери _Websites_ и укажи разрешённые домены:
     - `https://usm-life.<твой-поддомен>.workers.dev/*`
     - `https://web.telegram.org/*`
     - `https://t.me/*`
     - `http://localhost:*` (для локальной отладки)
   - **Установка в Worker:** Выполни в терминале:
     ```bash
     npx wrangler secret put GOOGLE_MAPS_BROWSER_KEY
     ```
     Worker безопасно передаёт этот ключ фронтенду через `/api/bootstrap` без сохранения в репозитории.

### Защита бюджета и лимиты запросов

- **Встроенный Rate Limit Worker:** На уровне Cloudflare Worker действует автоматический лимит: не более 30 запросов планирования маршрута в час на одного пользователя Telegram (таблица `trip_plan_rate_limit` в D1). При превышении возвращается код 429 с понятным уведомлением.
- **Кэширование:** Идентичные запросы координат (с точностью до 4 знаков) кэшируются на 2 минуты, что исключает повторные платные запросы к Google Routes API при частом обновлении.
- **Бесплатный уровень Google:** Google Cloud Platform ежемесячно предоставляет **$200 бесплатного кредита** на использование Maps и Routes API, чего с огромным запасом хватает для личного расписания.
- **Рекомендация по Budget Alerts:** В консоли Google Cloud перейди в **Billing → Budgets & alerts** и создай оповещение на $5 или $10. В разделе **APIs & Services → Quotas** для Routes API можно также выставить жёсткий дневной лимит (например, 500 запросов в день), чтобы полностью исключить непредвиденные расходы.
- **Плавный Fallback:** Если ключи Google Maps не заданы или превышен лимит, интерфейс не падает, а плавно отображает карту Кишинёва на базе Leaflet/CartoDB с живыми троллейбусами Tranzy.

## Tranzy, приватность и ограничения

- **Официальный API:** По актуальной OpenAPI-документации Tranzy ([Opendata API Docs](https://api.tranzy.ai/v1/opendata/docs), спецификация `https://api.tranzy.ai/v1/opendata/openapi.json`):
  - Эндпоинт транспорта: `https://api.tranzy.ai/v1/opendata/vehicles` (во множественном числе `/vehicles`). Прежний путь `/vehicle` возвращал HTTP 404 (`Cannot GET /v1/opendata/vehicle`). Адаптер Worker теперь автоматически нормализует путь, если в старых настройках остался суффикс `/vehicle`.
  - Авторизация и заголовки: в запросах используется заголовок `X-API-KEY` для ключа и `X-Agency-Id` для идентификатора транспортного оператора. Устаревший заголовок `X-City` спецификацией не поддерживается.
  - Определение агентства: эндпоинт `https://api.tranzy.ai/v1/opendata/agency` возвращает список доступных агентств. Адаптер Worker автоматически опрашивает `/agency` и находит агентство для Кишинёва (по таймзоне `Europe/Chisinau` или операторам RTEC / PUA). Также можно задать точный ID вручную через переменную `TRANZY_AGENCY_ID`.
  - Ограничения и квоты: при превышении лимита поставщик возвращает HTTP 429 (`Your API key has exceeded its request quota`). Опрос upstream выполняется по cron не чаще одного раза в 5 минут (переменная `TRANZY_REFRESH_MINUTES = "5"`), а пользователи Mini App читают кэшированное состояние из базы D1, что защищает ключ от исчерпания лимита.
  - Коды ошибок: при HTTP 403 API сообщает о неверном ключе или отсутствии прав к агентству; ошибки маскируют ключ в логах (`[скрыто]`).
- Ключ Tranzy не нужен для базовой работы: без него отображается базовая оценка ~30 минут. При наличии ключа добавляй его как Secret `TRANZY_API_KEY` в настройках Worker.
- Текущая интеграция отображает доступность сервиса и количество активных машин, но не гарантирует точное время прибытия и не заменяет знание расписания.
- D1 хранит расписание, домашние задания, настройки и адреса отдельно по Telegram ID. Адреса не выводятся в логи приложения. Данные не защищены мастер-паролем на телефоне, поэтому не храни здесь пароли или платёжные сведения.
- Для D1 существуют суточные квоты на бесплатном тарифе; при превышении запросы могут временно перестать выполняться ([лимиты D1](https://developers.cloudflare.com/changelog/post/2026-09-01-d1-free-tier-limit-enforcement/)). Настрой резервное копирование D1 до хранения важных данных.
- Cron Worker отправляет включённые напоминания о ДЗ, сне, подъёме и выходе из дома перед очными парами (с расчётом времени на дорогу и запаса). Telegram не заменяет системный будильник.
- В приложении укажи дату начала семестра и чётность первой недели, а также фактическую длительность английского, когда узнаешь её.

## Если возникла ошибка

- **Сборка не найдена:** проверь корневую папку `/`, имя Worker `usm-life` и build/deploy команды.
- **Ошибка D1:** проверь, что ID в `worker/wrangler.toml` соответствует базе, а SQL миграции выполнен в её Console.
- **401 в Mini App:** открывай приложение через Telegram-бота, не обычной вкладкой браузера.
- Mini App доступен пользователям Telegram с корректной сессией. Данные расписания, заданий и настроек каждого пользователя отделены по его Telegram ID.
- **Бот не отвечает:** проверь webhook в Cloudflare Logs и `getWebhookInfo` Telegram; проверь совпадение webhook secret.
- Для записи `console.error` и запросов явно включена Observability в `worker/wrangler.toml`. После следующего успешного деплоя открой Cloudflare Dashboard → **Workers & Pages** → **usm-life** → **Logs** → **Live** (в некоторых версиях панели раздел называется **Observability**). Запусти поток логов и повтори действие в Mini App.
- Если пункта Logs/Observability нет вообще, это вопрос интерфейса или прав аккаунта, а не отсутствие обращений к Worker. Убедись, что выбрана именно запись Worker `usm-life`, а не домен/страница проекта; при необходимости владелец аккаунта должен выдать роль с доступом к Workers Logs.
- Не записывай в логи токен, адреса, Telegram `initData` или тексты ДЗ.

## Обновление с админ-панелью сообщений

1. Проверь `ADMIN_USER_ID` в настройках Worker: это Telegram ID владельца.
   Дополнительные администраторы задаются в `ADMIN_USER_IDS`; в проекте указан `8624922366`.
2. Примени миграции к активной базе (D1 либо Turso), включая
   `0010_admin_broadcasts.sql`. Она добавляет журнал рассылок и отметку однократной
   инициализации расписания. Не публикуй новый Worker до этой миграции.
3. Выполни проверки типов, тесты и сборку. Затем опубликуй Worker с интерфейсом.
4. В Telegram открой «Настройки → Панель администратора» и проверь режим
   «Только мне». После проверки можно выбирать других получателей.

Публичный `/health` теперь только читает состояние. Параметры
`broadcast_weather`, `refresh`, `refresh_stops` не запускают действия.
Для сообщений используется только API администратора с Telegram-авторизацией.

## Контрольные и экзамены

Перед публикацией версии с разделом «Учёба» примени `0011_assessments.sql`:

```sh
npm run migrate
npm run deploy
```

Миграция добавляет отдельную таблицу `assessments`; существующие ДЗ и расписание сохраняются.
Напоминание выбирается отдельно в каждом событии. Проверка запускается раз в минуту;
если планировщик пропустил время напоминания, он отправит его до начала события.
Без указанного времени для напоминания используется 09:00 по Кишинёву.
Изменение даты, отмена напоминания, завершение и удаление события отменяют устаревшую отправку.


## Личные сроки и уведомления

Перед деплоем применить 0013_notification_preferences.sql. Погода и ежедневный план теперь включаются в настройках отдельно; время задаётся по Кишинёву. Пожелание добавляется к погоде по желанию. Тихие часы откладывают актуальные сроки, погоду и сводку; напоминания о подъёме, сне и выходе в это время пропускаются.

Сроки объединяют ДЗ, контрольные и экзамены без копирования данных. ДЗ из пары подставляет предмет и ближайшее неотменённое занятие с учётом чётности.


## Интервалы напоминаний о ДЗ

Перед публикацией применить `0014_homework_reminder_interval.sql`. Миграция добавляет индивидуальный интервал задания и сохраняет историю отправок, чтобы не повторить старые напоминания. Старые задания без своего интервала используют настройку по умолчанию.

В интерфейсе выбираются часы и дни. Если время сдачи не задано, отсчёт идёт от 09:00 даты срока по Кишинёву. Опоздавшие проверки отправляют напоминание, пока срок не наступил; выполненные и просроченные задания пропускаются. Общий переключатель уведомлений о ДЗ и тихие часы сохраняют силу.


## Оценки и вложения к ДЗ

Перед деплоем применить `0015_grades_and_attachments.sql`. Оценки хранятся отдельно для каждого пользователя: шкала 1–10, до двух знаков после запятой, вес 0,1–10. Средний балл учитывает веса; официальная формула университета не предполагается.

Приватные файлы используют binding `HOMEWORK_FILES` (Workers KV), метаданные — активную базу. До 5 файлов по 5 МБ на задание и 100 МБ на профиль. Поддерживаются JPG, PNG, WebP, PDF, DOC/DOCX, XLS/XLSX, PPT/PPTX, TXT; проверяются размер и сигнатура содержимого. Чтение требует Telegram-сессию; ссылки для скачивания действуют 5 минут. Бот-токен не передаётся клиенту.

Удаление вложения сразу закрывает доступ, а планировщик повторяет очистку хранилища при сбое. Удаление ДЗ оставляет записи для очистки файлов. Незавершённые загрузки старше часа также убираются. Создание ДЗ и оценок поддерживает повтор запроса без дубликатов.
