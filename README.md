# USM | Economice — Telegram Mini App

Личное расписание, домашние задания, утренний план и дорога до университета. Приложение построено на React 19 + Vite, Cloudflare Worker и базе данных Cloudflare D1 (SQLite). Worker отдаёт интерфейс и API, проверяет Telegram `initData`, обрабатывает webhook бота и запускает проверки по расписанию (Cron).

## Структура проекта

- `apps/web` — React 19 + Vite Mini App: интерфейс расписания, домашние задания, утренний план, настройки, темы (светлая, тёмная, розовая).
- `packages/shared` — чистые функции расчёта подъёма, сна, выхода, чётности недели и часового пояса Кишинёва с тестами `vitest`.
- `worker` — Cloudflare Worker: роутер API, авторизация Telegram `initData`, webhook, крон-уведомления и интеграция с Tranzy.
- `worker/migrations` — SQL-миграции Cloudflare D1.

## Сообщения пользователям и обновление базы

Панель доступна в «Настройки → Панель администратора». Права проверяются сервером
по подписанной Telegram-сессии. Укажи числовой Telegram ID владельца в переменной
Worker `ADMIN_USER_ID`. Если она не задана, сохраняется прежний ID владельца из проекта.
Дополнительные администраторы задаются в `ADMIN_USER_IDS` через запятую.
В конфигурации добавлен второй администратор `8624922366`; доступ владельца сохранён.

Перед публикацией этой версии примени миграцию `0010_admin_broadcasts.sql`
тем же способом, которым обновляется используемая база:

- Cloudflare D1: `npm run migrate:cloudflare`.
- Turso: `npm run migrate:turso`.

После миграции можно собрать и опубликовать Worker через `npm run deploy:cloudflare`.
Локальная проверка не выполняет публикацию, не меняет рабочую базу
и не отправляет настоящие сообщения.

В панели есть поиск по имени/ID, личная отправка, выбор до 100 получателей
и объявление всем. По умолчанию выбран режим «Только мне».
Перед отправкой показываются текст и получатели. Проверки автоматических сводок
тоже отправляются только администратору.

Рассылки обрабатываются короткими порциями по пять получателей, результаты
сохраняются в базе. Если закрыть приложение, оставшуюся отправку можно продолжить
из журнала. Повтор того же запроса не отправляет подтверждённые сообщения заново.
Если ответ Telegram потерян, доставка помечается как неподтверждённая и автоматически
не повторяется. «Принято Telegram» означает ответ API, а не прочтение пользователем.
Бот может писать только тем, кто разрешил ему сообщения; ошибки блокировки видны
в результатах.

Тесты используют локальную SQLite и заглушки Telegram; для новых интеграционных
тестов нужен Node.js 22.18+ (рекомендуется текущая LTS).

## Команды из корня проекта в Windows

- `npm run build` — проверка TypeScript и сборка интерфейса.
- `npm run deploy` — сборка и публикация Cloudflare Worker с сохранением текущих переменных.
- `npm run migrate` — миграции активной базы Turso; уже применённые файлы пропускаются.

Используй Node.js 22.18+ (на этом ПК установлен Node.js 24).
Конфигурация Vite загружается через `--configLoader native`, чтобы избежать
ошибки `spawn EPERM` при её предварительной сборке esbuild.
Секреты Turso для локальных команд находятся в исключённом из Git файле `worker/.dev.vars`.
